# 寄存器分配器

`allocator.py` 是一个不解析源语言/操作码的图着色寄存器分配器。输入仅描述：

- 至多 30 个基本块组成的控制流图；
- 至多 12 个临时变量；
- 每个变量的正整数溢出代价和 2～4 个可用寄存器；
- 每条指令先读取的变量集合 `reads`，以及随后定义的至多一个变量 `defines`。
- 调用类指令可列出 `clobbers`，表示执行期间会改写的物理寄存器；调用前后都需要保留的变量不能留在这些寄存器中。
- 变量可用 `pinned_register` 声明固定物理寄存器（硬约束），用 `prefer_same_as`
  与 `affinity_weight`（默认 1）声明与另一变量同寄存器的带权亲和提示（软约束）。

额外字段（例如 `op`）会被忽略，因此可用于保存源语言指令，但不影响分配。

## 输入格式

```json
{
  "entry": "b0",
  "variables": [
    {"id": "a", "spill_cost": 100, "registers": ["r0", "r1"]},
    {"id": "b", "spill_cost": 1, "registers": ["r0", "r1"]}
  ],
  "blocks": [
    {
      "id": "b0",
      "instructions": [
        {"op": "add", "reads": [], "defines": "a"},
        {"op": "use", "reads": ["a", "b"], "defines": null}
      ],
      "successors": ["b1"]
    },
    {
      "id": "b1",
      "instructions": [],
      "successors": []
    }
  ]
}
```

说明：

- `defines` 为 `null` 或省略表示指令不定义变量；
- `reads` 和 `successors` 省略时按空数组处理；
- `clobbers` 省略时按空数组处理；指令读取发生在改写前，定义发生在改写后；
  因此仅在该指令最后一次被读取的变量、以及该指令新定义的变量都不受这些
  `clobbers` 限制，只有在指令执行前后都存活（live_after 中且不是本指令定义）
  的变量必须避开它们；变量跨越多个调用点时，各调用点的 `clobbers` 取并集；
- `pinned_register` 省略或为 `null` 表示不固定；给定值必须出现在该变量的
  `registers` 中。未溢出的固定变量只能取该寄存器；保留它若无合法着色
  （例如与另一固定变量撞寄存器，或固定寄存器被它跨越的调用改写），
  枚举会把它选作溢出对象，而不会静默改派寄存器；
- `prefer_same_as` 必须引用另一个已声明变量；当两端都未溢出且最终着色相同
  时，该提示被满足并贡献 `affinity_weight`，用于并列代价下的裁决；
- 变量、基本块和寄存器名必须是非空字符串；
- 未知变量、非法后继、重复变量/基本块/寄存器名、重复后继以及 JSON 重复键都会整份拒绝。

## 算法

1. 用前驱后继关系计算活跃变量不动点。对每条指令反向扫描：

   ```text
   live_after(I) = live_out[B]（块内最后一条）或 live_before(下一条指令)
   live_before(I) = (live_after(I) - {defines(I)}) ∪ reads(I)
   live_out[B] = union(live_in[S], S ∈ successors(B))
   ```

   循环回边会由反复迭代直到不动点自然处理。

2. 从每个块的 `live_out` 开始反向扫描指令，建立干涉图，同时按「读取→改写→
   定义」的时序累计每个变量必须避开的调用改写寄存器（输出为
   `register_restrictions`）。指令按“先读取、后定义”处理：若一个变量只在当前
   指令被读取，而定义值在读取后才产生，则二者不干涉，允许复用寄存器。
3. 枚举全部溢出集合（最多 `2^12 = 4096` 个）。
4. 对每个候选集合，把溢出变量从干涉图删除，再用带回溯与前向检查的着色检查
   剩余变量。着色同时满足三类硬约束：
   - 干涉变量不能同寄存器；
   - 未溢出的固定变量只能取 `pinned_register`；
   - 变量不能取 `register_restrictions` 中的寄存器。
5. 按以下顺序选择唯一答案：
   - 总溢出代价最小；
   - 代价相同时，已满足亲和提示的 `affinity_weight` 总和（`affinity_gain`）最大；
   - 仍相同时，排序后的溢出变量 ID 序列字典序最小；
   - 仍相同时，按未溢出变量 ID 排序后的 `(变量, 寄存器)` 映射字典序最小。

寄存器按名称字典序枚举，因此同一溢出集合、同一亲和收益下得到字典序最小的
合法映射；亲和收益用「仍未着色的提示权重」做可纳上界剪枝，不会影响最优性。
固定变量发生无法调和的冲突（固定到被调用改写的寄存器、两个干涉变量固定到
同一寄存器等）时，由溢出枚举按同一裁决顺序决定溢出谁，全部溢出永远可行。

## 使用

从文件读取：

```bash
python3 allocator.py input.json
```

或从标准输入读取：

```bash
python3 allocator.py < input.json
```

成功时输出：

```json
{
  "liveness": {
    "b0": {"in": ["b"], "out": []}
  },
  "interference_edges": [["a", "b"]],
  "register_restrictions": {},
  "spilled": [],
  "spill_cost": 0,
  "affinity_gain": 0,
  "allocation": {"a": "r0", "b": "r1"},
  "preferences": {}
}
```

`register_restrictions` 只列出需要避开调用改写寄存器的变量；`preferences`
回显输入中的固定寄存器与亲和声明，便于把分配结果与约束逐条对照。

输入不合法时向标准错误输出 `{"error": "..."}`，退出码为 2；输出不会改写机器指令。

## 测试

```bash
python3 -m unittest -v test_allocator.py
```

测试包含：

- 循环回边的活跃变量不动点（含循环体内调用改写对回边活跃变量的限制）；
- 分支汇合造成的跨路径并存和干涉；
- 读取后定义导致的寄存器复用；
- 调用改写的时序边界（调用前最后读取、调用后新定义不受限）、块内与跨块
  活跃跨越调用、多个调用点的限制并集；
- 固定寄存器的强制着色，以及固定寄存器与调用改写、与另一固定变量冲突时
  按溢出代价裁决；
- 代价相同时优先满足带权亲和提示（着色内与溢出集合间两个层面），亲和也
  相同时回退到字典序规则；
- 未知变量、非法后继、重复块、JSON 重复键和数量/代价非法输入；
- 在小图上独立枚举全部溢出集合和全部着色，与主算法结果对拍。
