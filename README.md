# 寄存器分配器

`allocator.py` 是一个不解析源语言/操作码的图着色寄存器分配器。输入仅描述：

- 至多 30 个基本块组成的控制流图；
- 至多 12 个临时变量；
- 每个变量的正整数溢出代价和 2～4 个可用寄存器；
- 每条指令先读取的变量集合 `reads`，以及随后定义的至多一个变量 `defines`。
- 调用类指令可列出 `clobbers`，表示执行期间会改写的物理寄存器；调用前后都需要保留的变量不能留在这些寄存器中。
- 变量可声明 `pinned_register`（必须从 `registers` 中选取）：只要不被溢出，该变量就只能分配到该寄存器。
- 变量可用 `prefer_same_as`（另一个已声明变量，不能指向自身）配合正整数 `affinity_weight`（缺省 1）给出带权亲和提示：两个变量最终同色时，提示方获得其权重的收益。

额外字段（例如 `op`）会被忽略，因此可用于保存源语言指令，但不影响分配。

## 输入格式

```json
{
  "entry": "b0",
  "variables": [
    {"id": "a", "spill_cost": 100, "registers": ["r0", "r1"]},
    {"id": "b", "spill_cost": 1, "registers": ["r0", "r1"]}
  ],
  "blocks": [
    {
      "id": "b0",
      "instructions": [
        {"op": "add", "reads": [], "defines": "a"},
        {"op": "use", "reads": ["a", "b"], "defines": null}
      ],
      "successors": ["b1"]
    },
    {
      "id": "b1",
      "instructions": [],
      "successors": []
    }
  ]
}
```

说明：

- `defines` 为 `null` 或省略表示指令不定义变量；
- `reads` 和 `successors` 省略时按空数组处理；
- `clobbers` 省略时按空数组处理；指令时序为「先读取、再改写、后定义」：读取在改写前完成（本指令最后一次读取的变量不受限制），定义在改写后产生（本指令新定义的变量也不受限制）；只有在改写点之后仍然存活的其他变量不能使用被改写的寄存器；
- 变量、基本块和寄存器名必须是非空字符串；
- 未知变量、非法后继、重复变量/基本块/寄存器名、重复后继以及 JSON 重复键都会整份拒绝。

## 固定寄存器与亲和

- `pinned_register` 是硬约束：它把该变量的着色域收窄为单一寄存器。若该寄存器被变量跨越的某次调用改写，或多个固定条件无法同时满足，则必须溢出相关变量——所有变量都溢出总是合法的退路；
- 亲和提示是软约束，按条计分：变量 `a` 声明 `prefer_same_as: b` 且二者都未溢出并分到同一寄存器时，获得 `a.affinity_weight`；双向提示的两侧分别计分。任一方被溢出则该提示不产生收益。


## 算法

1. 用前驱后继关系计算活跃变量不动点。对每条指令反向扫描：

   ```text
   live_after(I) = live_out[B]（块内最后一条）或 live_before(下一条指令)
   live_before(I) = (live_after(I) - {defines(I)}) ∪ reads(I)
   live_out[B] = union(live_in[S], S ∈ successors(B))
   ```

   循环回边会由反复迭代直到不动点自然处理。

2. 从每个块的 `live_out` 开始反向扫描指令，建立干涉图，同时收集调用改写约束：

   ```text
   跨越改写点集合 crossing(I) = live_after(I) - {defines(I)}
   对每个 r ∈ clobbers(I)、v ∈ crossing(I)：v 的候选寄存器禁用 r
   ```

   `live_after` 由不动点的块边界活跃集与块内反向扫描共同决定，因此块内活跃、
   跨块活跃（含分支汇合与循环回边）以及同一变量跨越多个调用点的情况都会被
   合并为逐变量的一元禁用集合，与干涉边一起约束着色。

   指令按“先读取、后定义”处理：若一个变量只在当前指令被读取，而定义值在读取后才产生，则二者不干涉，允许复用寄存器。
3. 枚举全部溢出集合（最多 `2^12 = 4096` 个）。
4. 对每个候选集合，把溢出变量从干涉图删除；着色域再扣除调用改写禁用寄存器；
   固定变量的域收窄为其 `pinned_register`。随后用带回溯的着色检查可行性，
   并用亲和收益上界做分支限界，找出该溢出集合下收益最大、字典序最小的映射。
5. 按以下顺序选择唯一答案：
   - 总溢出代价最小；
   - 代价相同时，排序后的溢出变量 ID 序列字典序最小；
   - 仍相同时，已满足亲和提示的权重总和最大（`affinity_gain`）；
   - 仍相同时，按未溢出变量 ID 排序后的 `(变量, 寄存器)` 映射字典序最小。

寄存器按名称字典序枚举，收益并列时先找到的解即字典序最小映射；原有的代价
与并列裁决规则完全保留，亲和收益只是插入在映射字典序之前的新一级裁决。

## 使用

从文件读取：

```bash
python3 allocator.py input.json
```

或从标准输入读取：

```bash
python3 allocator.py < input.json
```

成功时输出：

```json
{
  "liveness": {
    "b0": {"in": ["b"], "out": []}
  },
  "interference_edges": [["a", "b"]],
  "clobber_restrictions": {},
  "spilled": [],
  "spill_cost": 0,
  "affinity_gain": 0,
  "satisfied_affinities": {},
  "allocation": {"a": "r0", "b": "r1"}
}
```

其中：

- `clobber_restrictions` 列出每个变量因跨越调用而被禁用、且属于其候选集合的寄存器（空时不出现）；
- `affinity_gain` 是最终方案兑现的亲和权重总和；
- `satisfied_affinities` 逐条给出每条亲和提示的伙伴、权重与是否满足（伙伴或自身被溢出即为不满足）；
- `preferences` 回显所有固定寄存器或亲和声明，便于对照解释。

输入不合法时向标准错误输出 `{"error": "..."}`，退出码为 2；输出不会改写机器指令。

## 测试

```bash
python3 -m unittest -v test_allocator.py
```

测试包含：

- 循环回边的活跃变量不动点；
- 分支汇合造成的跨路径并存和干涉；
- 读取后定义导致的寄存器复用；
- 调用前后活跃变量避开 `clobbers`：调用前最后一次读取、调用后新定义不受限，块内/跨块活跃、多个调用点的禁用寄存器合并，全部被禁用时溢出；
- 固定寄存器硬约束：相互冲突的固定条件或固定色被调用改写时必须溢出；
- 亲和收益在代价与溢出集合并列时优先于映射字典序，代价仍优先于收益，溢出伙伴不产生收益；
- 代价相同、溢出集合相同以及寄存器池受限时的字典序规则；
- 未知变量、非法后继、重复块、JSON 重复键和数量/代价非法输入；
- 在小图上独立枚举全部溢出集合和全部着色（含改写禁用、固定寄存器与亲和收益的完整裁决键），与主算法结果对拍。
